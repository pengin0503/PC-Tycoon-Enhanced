## 2. 共通の互換規則

- セーブは `version: 1` のまま。新しい状態はすべて optional／default 付きで追加し、既存 JSON はそのまま読み込める。
- 決定論: 新しい乱数はすべて状態内の `seed`（既存の xorshift32）から取る。同じ初期状態とコマンド列なら同じ結果。
- 新しい係数は `packages/content` に置き、シミュレーションは `packages/sim` の純粋関数で行う。
- 既存テストは、仕様を意図的に変えた箇所（研究ポイント化、技術数、UI 名称）だけを更新し、削除しない。

## 3. G2 — 部品

1. **電源 (PSU)** を `hardwareKinds` に追加: 定格出力 W、変換効率 %、モジュラー方式（なし/セミ/フル）。
   研究ドメインが 1 つ増え、技術数は 3040 → 3345（6 系統 × 50 + 外観 5）。
2. 完成 PC・ノートの部品枠に `psu` を追加（**任意**）。指定時は、合計消費電力 × 1.2 以下の定格なら組立不可。
   省略時は汎用電源を自動使用（既存セーブの完成 PC はこの扱い）。汎用電源 `v-psu` を部品一覧に追加。
   部品キーは `deviceSlots` 定数に一本化し、製造・調達・検証・買収での参照を共通化する。
3. **CPU キャッシュ** (MB) を CPU の仕様に追加。項目に「後から追加された既定値」を持たせ、旧製品の仕様に無い場合は既定値で評価する。
4. **工場 13 段階**: 上限を 10 → 13。

## 4. G1 — 製品サイクル

1. **ベンチマーク**（純関数）: 部品は種類別の指標、完成 PC・ノートは CPU/GPU/ストレージ/総合スコアと、
   架空ゲーム 5 本の推定 FPS（解像度・設定別）を算出。OS の動作要件を満たさない場合はペナルティ。
2. **レビュー**: 発売時に一度だけ確定。評価軸は 性能（同種の発売済み製品の最高値との比）、価格対性能、品質（信頼性）、
   デザイン（外観グレード）、革新性（自社の同種前製品からの伸び）。100 点満点 → 星 0.5 刻み 1〜5。
   架空メディア 4 社のコメントを生成し、製品に `review` として保存。需要に 0.7〜1.35 倍で作用する。
3. **ファン**: `company.fans`（既定 0）。発売時にレビューと認知度に応じて増加、週次で販売本数・広告・販売店に応じて増加し、
   0.5% 減衰する。需要に `1 + log10(1+fans)/20`（上限 1.4）で作用する。
4. **発売プレゼンテーション**: `launch` に任意の `presentation`（none / online / event / keynote）。
   費用と引き換えに製品ごとの「話題性 (hype)」を与え、需要に上乗せして週次で減衰する。発売時のファン獲得も増える。

## 5. G3 — 経営

1. **研究ポイント (RP)**: `company.researchPoints`（新規ゲームは 100、旧セーブは 0）。週次で
   `(基礎 10 + 研究職スキル × 0.1) × 10 × オフィス倍率 × 特性倍率` を獲得。
   研究は RP を消費して**即時完了**（費用 = 旧作業量 × 10、高難度 ×1.3、長期モード ×2）。現金は使わない。
   研究枠は廃止。旧セーブの進行中研究は従来の週次処理で完了させる。
2. **販売店（流通網）**: `distributionLevel` 0〜10。投資で需要 +6%/段階、ファン獲得を増やす。維持費は月次。
3. **大口取引の打診**: 月次で一定確率、在庫のある発売済み製品に買い手が数量と単価を提示する（14 日で失効）。
   「承諾」「見送り」「値上げ交渉（上乗せ率 %）」。交渉の成功確率は上乗せが大きいほど下がる（0% → 100%、25% 以上 → 0%）。
4. **買収交渉**: `acquire` に任意の `offer`。評価額以上なら成立。70〜100% の範囲では、70% で 10% から 100% で 100% へ上がる確率で成立し、
   不成立なら 30 日間は再交渉できない。`offer` 省略時は従来どおり評価額で買収。
5. **人事**: 採用時に特殊スキル（天才・効率家・カリスマ・倹約家・AI 専門・なし）を決定論的に付与。
   **候補者リスト**（月次で 3 名を無料更新、**有料の人材探し**で高スキル候補を取得）、**解雇**（給与 3 か月分の退職金）。
   従来の `hire {role, skill}` も残す。

## 6. G4 — OS

1. 機能を拡張: ファイル・電卓・ブラウザに加え、セキュリティ・メディア・ゲーム・アプリストア。
2. **動作要件**: 機能数とバージョンから最低 CPU/RAM/ストレージを算出。バンドルする完成 PC が満たさない場合は性能が低下する。
3. **ロック画面とテーマ**（壁紙・アクセント色）を OS 仕様として保存し、仮想デスクトップで**インストール画面 → ロック画面 → デスクトップ**を順に表示する。
4. **ハッカー攻撃**: 発売済み OS がある場合、月次の確率で攻撃が発生（期限 7 日）。UI のミニゲームで侵入を撃退し、`defendAttack {blocked, total}` を送る。
   撃退できなかった割合に応じて評判・ファン・OS 需要が低下し、セキュリティ機能とサポート品質で被害が減る。期限切れは全被害。
5. **ゲームテスト**: 仮想デスクトップの「ゲーム」アプリで、自社 PC × OS の架空ゲーム FPS を表示する。

## 7. G5 — モードと進行

1. **ゲームモード** `mode`: standard / tycoon（簡易: 需要 +20%・研究費 -25%）/ long（研究費 ×2・競合の開発速度 0.7）/ sandbox（資金・RP・ファンを自由に設定できる。実績は無効）。
   難易度（通常／高難度）とは独立に選ぶ。
2. **ゲームオーバー**: 高難度で月次決算後に未払債務が残った場合、`gameOver` を記録し、以後の操作を拒否する。
3. **実績**: 累計収益・現金残高・販売本数・ファン数・年間売上・企業価値の段階実績と、オフィス最大・工場最大・全部品カテゴリ・全社買収などを判定し、解除日を保存。
4. **社名変更とロゴ**（独自 SVG のロゴ 24 種）。

## 8. UI（原作の画面の流れに寄せる）

- **ホーム = オフィス画面**: 中央に段階で変わるオフィスと工場のイラスト、上部 HUD に 現金・研究ポイント・ファン・日付・速度、
  下部に大きなアイコンボタンのメニュー。
- **開発**: カテゴリタイルを選ぶ → 仕様スライダー（グループ別タブ）→ 外観（デザイン）選択 → 名前・価格 → 開発開始。
  開発完了後、製品一覧から **発売プレゼン**（全画面スライド、スキップ可）→ **レビュー結果**（星と媒体コメント）→ 生産量と価格。
- **製品**: 製品ごとに売上・在庫・レビュー・ベンチマーク。値下げ・生産量の調整。
- **アップグレード**: オフィス／工場／販売店のタブ。
- **人事**: 候補者・人材探し・社員一覧（特性・育成・解雇）。
- **企業**: 競合一覧・買収交渉・大口取引。
- **統計**: 財務・製品成績・市場イベント・実績。
- **設定**: セーブ・JSON・UI サイズ・社名とロゴ。
- 明るい配色のモバイル向けタイクーン UI とする。既存のアクセシビリティ規則（ラベル、タッチ目標 36px 以上、内部スクロール、
  Android の戻る操作、50〜150% の UI サイズ）は維持する。
