# GitHub Issues 12–21 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the ten reviewed gameplay, persistence, accounting, and Android UX issues in GitHub #12–#21.

**Architecture:** Keep simulation rules in `packages/sim`, save behavior in `packages/save`, and transient interaction behavior in `apps/web`. Each issue gets a focused regression test before its implementation. Existing version-1 saves remain loadable through schema defaults and migration-safe fields.

**Tech Stack:** TypeScript, Zod, Vitest, Playwright, React, IndexedDB.

**Spec:** GitHub Issues #12–#21 in `pengin0503/PC-Tycoon-Enhanced`.

## Global Constraints

- Preserve deterministic simulation behavior for the same seed and commands.
- Do not remove or rewrite user save rows during recovery.
- Keep money and inventory accounting single-counted and integer-valued.
- Preserve existing version-1 save compatibility.
- Android Back consumes one visible UI layer at a time and does not dismiss mandatory decisions.

## Review Focus

- Legacy saves with missing or stale sequence fields retain unique employee IDs.
- Subscription service stops, repricing, and saves preserve earned but unsettled revenue.
- Corrupt rows do not hide valid save slots or get silently deleted.
- Bulk PC sales allocate bundled OS revenue and cost once.
- Derived cluster values and demand allocations remain schema-valid and deterministic.
- Paused/hidden time does not advance foreground-only defense UI.
- Back handling respects focus, overlays, nested screens, and mandatory dialogs.
